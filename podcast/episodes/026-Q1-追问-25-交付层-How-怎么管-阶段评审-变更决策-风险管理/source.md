**学生版一句话**

交付层就是「把产品定义变成真机、再变成批量交付、最后管到生命周期结束」的过程。产品经理不是所有工种，而是总协调人，要对「是否按时、按质量、按成本交付」负责。

**一个比喻**

交付层像拍电影。硬件、结构、固件、测试、认证、供应链、生产和售后是不同工种，产品经理是导演：定拍摄计划、开评审会、控制剧本变更、管理超支风险。导演不亲自演所有角色，但电影砸了，导演要负责。

**交付层的四项核心职责**

1. 建立跨职能协作机制，让八条线的人用同一套节奏工作。
2. 用阶段门控制质量和风险，不到标准不进入下一阶段。
3. 用变更控制保护已冻结的规格、成本和计划。
4. 用风险登记册持续管理技术、供应、质量和进度风险。

**1. 跨职能协同与职责边界**

| 职能 | 他们负责什么 | 产品经理要盯什么 | 常见冲突 |
| --- | --- | --- | --- |
| 硬件 | 原理图、PCB、选型、硬件测试 | 硬件需求是否落地、成本是否超 BOM | 硬件想加功能，成本和进度超 |
| 结构 | 外壳、散热、防护、安装方式 | IP 等级、模具周期、可制造性 | 结构改动慢，影响量产 |
| 固件 | 协议栈、边缘计算、OTA、驱动 | 功能验收、性能指标、稳定性 | 固件测试不足，现场才暴露 |
| 测试 | 功能、性能、环境、可靠性、EMC | 测试计划覆盖规格书，问题闭环 | 测试发现太晚，进度被动 |
| 认证 | CE、FCC、CCC、UL、RoHS、行业合规 | 认证预算、周期、风险预判 | 认证失败，返工周期长 |
| 供应链 | 选型、采购、MOQ、交期、备料 | 关键物料交期、替代料、成本 | 缺料导致停产 |
| 生产 | 试产、量产、良率、工艺 | PVT 通过、良率目标、产能 | 工艺问题影响交付质量 |
| 售后 | 安装、维修、RMA、备件、客户反馈 | 返修率、问题回流、服务成本 | 售后问题研发不认 |

**RACI 工具**

RACI = Responsible（执行）、Accountable（最终负责）、Consulted（咨询）、Informed（告知）。

| 活动 | 产品经理 | 硬件 | 固件 | 测试 | 供应链 | 生产 | 售后 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 需求冻结 | A | C | C | C | C | I | C |
| 原理图评审 | C | R/A | C | C | C | I | I |
| 固件验收 | A | I | R | C | I | I | I |
| 认证送测 | A | C | C | R | C | I | I |
| 试产放行 | A | C | C | C | C | R | I |
| 售后问题闭环 | A | C | C | C | I | I | R |

注意：Accountable 只能有一个，不能两个部门都说「最后我负责」。

**2. 阶段门（Stage-Gate / Phase-Gate）**

阶段门是硬件交付最成熟的框架之一。每个阶段结束设一道门，只有满足通过标准才能进入下一阶段。

工业网关项目的阶段门：

| 门 | 名称 | 主要交付物 | 通过标准示例 |
| --- | --- | --- | --- |
| G0 | 立项评审 | 商业论证、需求、资源计划 | 商业模型成立，目标毛利 ≥ 45%，有种子客户 |
| G1 | 方案冻结 | 产品定义、系统架构、规格书、BOM 预估 | 规格可测量，技术方案可行，认证和供应链风险明确 |
| G2 | EVT 评审 | 工程样机、功能测试、性能测试 | 核心功能通过，问题清单有闭环计划 |
| G3 | DVT 评审 | 环境测试、EMC 测试、认证预测试、试点 | 环境/EMC 通过，认证风险可控，试点反馈纳入计划 |
| G4 | PVT 评审 | 试产数据、良率、工艺文件 | 直通率 ≥ 95%，单位成本达标，可量产 |
| G5 | 上市评审 | 定价、渠道、客户、售后、培训 | 首批客户可交付，售后能力和备件到位 |
| G6 | 生命周期评审 | 销量、返修、成本、EOL 计划 | 决定继续、迭代还是退市 |

**阶段评审怎么开**

1. 会前：产品经理准备 Gate Deck，每个负责人提交 Check List，禁止空手开会。
2. 会中：按「质量、成本、进度、风险」四个维度打分，只讨论证据，不讨论感觉。
3. 会后：输出正式决策，包括 Go、No-Go、条件通过、打回重做。
4. 遗留问题必须有 owner、截止日期、验证方式。

**Gate Scorecard 评分表**

| 维度 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 质量 | 大量未闭环问题 | 主要问题已闭环 | 所有标准通过 |
| 成本 | 超目标 10% 以上 | 接近目标 | 达到或优于目标 |
| 进度 | 延误超过 4 周 | 延误 1 到 2 周 | 按计划 |
| 风险 | 有高风险无对策 | 有对策但未验证 | 风险受控 |

平均分低于 3 分不建议放行。

**3. 变更决策**

**为什么必须控制变更**

硬件变更成本随时间指数上升：

```text
方案阶段改需求：改文档
EVT 阶段改：改原理图、PCB、固件
DVT 阶段改：改测试、认证、模具
PVT 阶段改：改工装、改产线、改售后
量产后改：召回、返工、客户赔偿
```

所以硬件项目必须有「冻结点」和「变更控制委员会」。

**变更流程**

```text
提出变更请求
→ 影响评估（技术、成本、进度、质量、风险）
→ CCB 评审
→ 批准 / 拒绝 / 条件批准
→ 实施并更新基线
→ 记录变更日志
```

**影响评估至少回答七个问题**

1. 改了什么？为什么改？
2. 影响哪些硬件、结构、固件、测试？
3. 成本增加多少？
4. 进度推迟多久？
5. 质量和可靠性风险是什么？
6. 已生产库存怎么办？
7. 客户合同和认证有没有影响？

**变更严重级别**

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| A 级 | 影响安全、合规、核心功能 | 必须修复，进入 CCB 紧急评审 |
| B 级 | 影响体验、性能、交付 | 尽量在冻结点前完成 |
| C 级 | 优化项、非核心 | 放入下一版本 |

**常见冻结点**

| 冻结点 | 内容 |
| --- | --- |
| G1 方案冻结 | 功能、性能、接口规格 |
| EVT 结束 | 原理图、PCB 设计冻结 |
| DVT 结束 | 结构、外壳、固件主版本冻结 |
| PVT 开始 | BOM、供应商、工艺冻结 |
| 量产后 | 只允许安全和必须变更 |

**CCB 成员**

产品经理（主持人）、研发负责人、测试负责人、供应链负责人、生产负责人、质量负责人、必要时加入财务、法务和认证。

**4. 风险管理**

**风险登记册字段**

| 字段 | 内容 |
| --- | --- |
| 编号 | R-001 |
| 风险描述 | 4G 模组交期延长 |
| 类别 | 供应链 |
| 概率 | 高 / 中 / 低 |
| 影响 | 交付延迟 4 周 |
| 风险等级 | 高 |
| 责任人 | 供应链负责人 |
| 应对策略 | 备选模组、提前锁料 |
| 触发条件 | 交期超过 12 周 |
| 应急计划 | 启用备选方案 |
| 状态 | 跟踪中 |

**风险矩阵**

风险等级 = 概率 × 影响。

| 概率\影响 | 低 | 中 | 高 |
| --- | --- | --- | --- |
| 高 | 中 | 高 | 高 |
| 中 | 低 | 中 | 高 |
| 低 | 低 | 低 | 中 |

红色高风险必须每周跟踪，黄色中风险指定 owner，绿色低风险记录即可。

**FMEA**

FMEA = Failure Mode and Effects Analysis，失效模式与影响分析。

风险优先数 RPN = 严重度 × 发生频度 × 可检测度。

| 类型 | 分析对象 |
| --- | --- |
| DFMEA | 硬件设计失效：电源过压、接口损坏、过热 |
| PFMEA | 生产过程失效：贴片虚焊、装配不良、测试漏检 |
| SFMEA | 软件/固件失效：死机、数据丢失、OTA 失败 |

**工业网关常见风险**

| 风险 | 典型影响 | 应对 |
| --- | --- | --- |
| 芯片或模组缺货 | 停产、延期 | 双供应商、安全库存 |
| 认证不通过 | 无法销售 | 预测试、预留返工时间 |
| 环境测试失败 | 客户现场故障 | 宽温、防护等级冗余设计 |
| 固件问题晚发现 | 返修率高 | 试点、老化测试、日志上报 |
| 良率低 | 成本超支 | PVT 数据门控 |
| 客户频繁改需求 | 进度失控 | 冻结点 + 变更收费机制 |
| 售后问题不回流 | 重复犯错误 | 故障闭环流程 |

**应对策略四选一**

- 规避：换掉高风险方案。
- 降低：加测试、加冗余、双供应商。
- 转移：买保险、让供应商承担。
- 接受：低概率低影响，记录并观察。

| 跨职能周会 | 每周 | 进度、风险、变更、问题 |

**6. 常用文档**

- Gate Deck：阶段门汇报材料。
- DCR：变更请求单。
- Risk Register：风险登记册。
- Open Issues List：未决问题清单。
- Action Tracker：行动项跟踪表。
- Decision Log：决策记录。
- Change Log：变更日志。

**7. 常见失败原因**

- 产品经理变成传声筒，不推动决策。
- 阶段门流于形式，领导一句话放行。
- 没有冻结点，需求一直漂移。
- 变更只评估成本，不评估认证和售后。
- 风险只看进度，不看供应、质量、合规。
- 供应链问题太晚暴露。
- 售后问题没有回流到研发。

**8. 学生练习题**

用「工业网关」项目练习：

1. 写出 G1 到 G5 每个阶段的三条通过标准。
2. 列出 8 个常见风险，填入风险登记册。
3. 假设客户要求把 4G 改成 5G，写一份变更影响评估。
4. 为硬件、固件、测试、供应链各写一条 RACI 规则。

练习目标：拿到一个硬件项目，30 分钟内能说清楚阶段门、变更流程、风险清单和每个角色该给什么。
